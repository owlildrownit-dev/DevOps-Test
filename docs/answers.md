# **Теоретические вопросы**

## Вопрос № 1. Чем отличается git pull от git fetch?

    - Команда git pull позволяет скачивать изменения/обновления и сразу же пытаться интегрировать в текущую локальную ветку.

    - В то время, как команда git fetch только скачивает изменения/обновления и обновляет ссылки на ветки при этом не пытаясь сразу интегрировать в текущую ветку, позволяя сначала подробно просмотреть/проверить что именно изменено/обновлено было. И таким оьразом после проверки можно уже будет интегрировать изменения/обновления.

## Вопрос №2. Чем в linux отличается soft link от hard link? Какое поведение будет при удалении файла оригинала? Можно ли создать hardlink на директорию?

    - Soft link это отдельный файл по сути, хранящий путь к другому файлу или директории.

    - А hard link это можно сказать дополнительное имя для того же файла (оригинала), указывающее на тот же "inode".
   
    - При удалении оригинала в случае soft link, ссылки останутся, но станут битыми и не будут работать соответственно.
   
    - В hard link же при удалении оригинала, ссылки будут работать до тех пор, пока не будут удалены все ссылки hard link соответственно.
   
    - Hard link на директорию создать нельзя, только на файлы.

## Вопрос №3. Как проверить сетевую доступность между двумя linux машинами?

    - Сначала базово стоит проверить ping <IP>.
   
    - Далее можно проверить маршрут до узла посредством traceroute <IP> или tracepath <IP>.
   
    - Затем уже можно проверять сервис и/или порт через telnet <IP> <PORT>, nc -zv <IP> <PORT> или curl <http://...:8080>

## Вопрос №4. На каких компонентах Linux основана контейнеризация в Docker?

    - Основные компоненты это:

1. namespaces - изолируют процессы, файловую систему, сеть, пользователей и другие ресурсы.
2. cgroups - ограничение и учет ресурсов (CPU, RAM и др.).
3. capabilities - дают возможность выдавать процессу конкретные права, а не выдавать root.
4. union/overlay filesystem - используется для слоев образов и контейнеров.

## Вопрос №5. Почему вместо "COPY../RUN npm install" рекомендуют делать "COPY package.json/ RUN npm install/COPY.."?

    - Это по сути будет отделение файлов зависимостей от остального кода, чтобы Docker мог кэшировать установленные зависимости и не переустанавливать их каждой раз без необходимости.
   
    - Данный подход значительно ускоряет процесс сборки.

## Вопрос №6. Могут ли два контейнера внутри одного пода в Kubernetes слушать один и тот же порт?

    - Нет, не могут, так как контейнеры внутри одного пода используют общий network namespace, и при попытке назначить двум контейнерам один порт будет конфликтная ситуация.

## Вопрос №7. Какие виды JOIN знаете и чем они отличаются?

1. INNER JOIN - возвращает только те строки из таблиц, где есть совпадения.
2. LEFT JOIN - возвращает все строки из левой таблицы, а также строки, где есть совпадения из правой. При этом, в случае отсутствия совпадения, справа будет отображаться значение NULL.
3. RIGHT JOIN - то же самое что и LEFT JOIN, только наоборот.
4. FULL OUTER JOIN - возвращает все строки из таблиц. В случае отсутствия совпадения, будет отображаться значение NULL.

## Вопрос №8. Что такое having в SQL запросе? Чем отличается от WHERE?

    - HAVING возвращает необходимый запрос после группировки строк, в то время, как WHERE возвращает необходимый запрос только по строкам, до того как происходит группировка.
